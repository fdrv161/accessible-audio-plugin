# Проверка: автоматическая и ручная

Содержание: 1. Тесты клавиатурной маршрутизации. 2. Статические проверки.
3. Ручной план NVDA + REAPER. 4. Шаблон заметки к итерации. 5. Шаблон
отчёта об ошибке доступности.

## 1. Тесты клавиатурной маршрутизации

Речь скринридера в CI не проверишь, а маршрутизацию клавиш — можно: создай
процессор и редактор в консольном тесте и вызывай `keyPressed` напрямую.

```cpp
LSampler24AudioProcessor p (testFolder);
auto editor = std::make_unique<LSampler24AudioProcessorEditor> (p);
auto key = [] (int code, int mods = 0, juce::juce_wchar ch = 0)
{ return juce::KeyPress (code, juce::ModifierKeys (mods), ch); };

require (! editor->keyPressed (key (juce::KeyPress::spaceKey), slotCell),
         "On the main page Space belongs to the host transport");
require (editor->keyPressed (key (juce::KeyPress::returnKey), slotCell), "Enter opens parameters");
require (editor->keyPressed (key ('Z', juce::ModifierKeys::ctrlModifier, 'z'), grid),
         "Grid consumes unrelated host Ctrl commands");
require (editor->keyPressed (key (juce::KeyPress::escapeKey), grid), "Escape returns to slots");
```

Что стоит проверять:
- какие клавиши поглощаются, а какие намеренно отдаются DAW;
- навигация попадает на нужный элемент (индекс, категория);
- Escape возвращает на предыдущий уровень;
- края списков: повторное нажатие на краю ничего не меняет;
- что title элемента после действия равен ожидаемой строке (это то, что
  прочитает NVDA+Стрелка вверх).

В отчёте честно пиши: «маршрутизация проверена тестом; речь NVDA требует
проверки в хосте».

## 2. Статические проверки

- `scripts/a11y_audit.py` из этого навыка — общие ошибки.
- Свои маленькие скрипты-«стражи» на конкретные исправленные баги
  (LSampler-24, `verify-test114-ctrl-shift-a.py`: проверяет, что в условиях
  Ctrl+Shift+A нет `!isCommandDown()`). Дёшево и не даёт багу вернуться.
- Скрипт контракта параметров: количество, уникальность ID и хешей, порядок
  по манифесту, отсутствие запрещённых ID.
- Аудио-регрессия, если правишь DSP: побитовое сравнение с замороженной
  эталонной версией рендера (LSampler-24 держит копию TEST59 с SHA-256).

## 3. Ручной план NVDA + REAPER

Выполнять с NVDA (и при возможности с JAWS и Экранным диктором), REAPER с
OSARA. Каждый пункт — ожидаемая фраза.

1. Вставить плагин на трек, открыть окно (FX Chain и отдельное окно).
   NVDA называет первый элемент, фокус внутри плагина.
2. Пройти Tab/Shift+Tab по всем элементам: у каждого имя, роль, горячая
   клавиша; нет «безымянных» и «unknown».
3. Стрелки на главном списке: каждая строка короткая и понятная; на краях
   тишина.
4. NVDA+Стрелка вверх на каждом экране: читается текущая строка, без
   старых сообщений.
5. Изменение значения: слышно только новое значение, один раз.
6. Каждый модальный экран: открыть горячей клавишей и кнопкой, поработать,
   Escape — фокус вернулся (после кнопки — на кнопку, после горячей клавиши
   — на главный элемент).
7. Нажать неиспользуемые буквы, Ctrl+Z, Ctrl+S, пробел в модальном экране:
   REAPER ничего не делает.
8. Пробел на главном экране: запускает транспорт REAPER (если так задумано).
9. Долгая операция: начальная фраза, проценты по NVDA+Стрелка вверх,
   Alt+Tab в другое окно во время операции — плагин не «кричит» оттуда,
   возврат — итоговое сообщение и фокус на прежнем месте.
10. Закрыть окно плагина во время операции и открыть снова.
11. Список параметров FX в REAPER / OSARA: имена, значения, ввод значения
    текстом.
12. Ctrl+Shift+A (если есть): огибающая появляется/выключается, NVDA
    говорит строку с «Auto» / без; два экземпляра плагина на разных треках.
13. Уход фокуса из плагина во время прослушивания — звук остановился.
14. CLAP-версия: шаги 1–5 и 11.
15. Сохранить проект, закрыть, открыть: значения и автоматизация на месте.

## 4. Шаблон заметки к итерации

Каждая правка — короткий текстовый файл (в LSampler-24 — `TESTnnn_…_NOTE.txt`):

```text
<Плагин> TEST<номер> - <коротко о сути>

Base: TEST<предыдущий>.

Changes:
- <что изменено, с клавишами и точными фразами озвучки>

Not changed:
- DSP, parameter IDs and order, preset format, other shortcuts.

Verified:
- <тест/скрипт: PASS> | Not compiled locally (build via GitHub Actions).

Test in <DAW> with <скринридер>:
1. <шаг> -> expected: "<фраза>"
2. ...
```

Раздел «Not changed» не формальность: он говорит пользователю, что можно не
перепроверять.

## 5. Шаблон отчёта об ошибке доступности

Попроси пользователя прислать (взято из ToneTrace):
- Windows/macOS и версия, DAW и версия, версия плагина и формат (VST3/CLAP);
- скринридер и мост (например NVDA + OSARA);
- через что работал: окно плагина или список параметров хоста;
- шаги, что ожидалось услышать и что было услышано на самом деле.
