# Чек-лист аудита доступности плагина

Проходи по порядку. Для каждого пункта: «выполнено», «нарушено (где)»,
«не применимо». Уровни: К — критично (плагин непригоден), В — важно
(путаница, лишние усилия), У — удобство.

## Озвучка

- К. Явные сообщения на Windows идут через UIA Notification, а не
  `AccessibilityHandler::postAnnouncement` (SAPI-голос, NVDA не слышит).
- К. Результаты действий (загрузка, сохранение, ошибки, переключение
  режимов) озвучиваются.
- В. Нет двойной озвучки (фокус + анонс, titleChanged + анонс).
- В. Временные сообщения не записываются в title/description элементов.
- В. Фразы короткие: «Имя, значение»; при изменении — только значение.
- В. Варианты — подписями, числа с единицами, без лишних нулей.
- В. Ошибки говорят, что случилось и что делать.
- У. Края списков тихие; «некуда идти» объясняется один раз.
- У. Прогресс не чаще раза в 4 с и только при фокусе в плагине.

## Фокус

- К. При открытии окна фокус внутри плагина на осмысленном элементе.
- К. Фокус никогда не остаётся на скрытом/выключенном элементе.
- К. После закрытия любого экрана/диалога/меню фокус возвращается в
  предсказуемое место.
- В. Порядок Tab логичен и совпадает со зрительным; модальные экраны
  циклят Tab внутри себя.
- В. Уход фокуса из плагина останавливает прослушивание.

## Клавиатура

- К. Каждое действие доступно с клавиатуры (нет мышь-only контролов:
  компонентов с `mouseDown` без обработки клавиш и фокуса).
- К. Всё, что открывается правым кликом, открывается и Shift+F10 на
  элементе с фокусом.
- К. Модальные экраны поглощают все клавиши (в т.ч. отпускание), ничего не
  утекает в DAW.
- К. Нет условий `isCtrlDown() && !isCommandDown()` (на Windows всегда
  ложно).
- В. Единая модель клавиш на всех экранах (навигация отдельно от
  изменения).
- В. Escape везде закрывает/выходит на уровень выше.
- В. Горячие клавиши указаны в description кнопок и в справке.
- В. Пробел на главном экране не отнимается у транспорта DAW без явного
  режима.
- У. Поиск по первой букве в длинных списках; Shift+буква — назад.
- У. Ctrl+Home/End, Page Up/Down в длинных списках.

## Элементы

- К. У всех фокусируемых элементов есть имя (title), у иконок-кнопок тоже.
- В. Ползунки с единицами отдают текстовое значение, а не проценты.
- В. Поля только для чтения позволяют читать текст стрелками
  (видимая каретка), Tab не вставляет символ.
- В. Графика и метры исключены из дерева доступности
  (`setAccessible(false)`), а их информация есть текстом.
- В. Одинаковые по звучанию элементы различимы (уникальные имена).
- У. ComboBox поддерживает Home/End.

## Диалоги, меню, файлы

- К. Нет синхронных модальных циклов (`runModalLoop`, `showMessageBox`).
- В. Подтверждения: клавиши Y/N/Escape, фокус на безопасном «No», текст
  называет, что будет потеряно.
- В. Меню имеют заголовок; отмена возвращает фокус.
- В. Внутренний браузер файлов: модель клавиш как у списков, память
  позиции, прослушивание как режим On/Off.
- У. Повторное открытие меню на последней команде.

## Параметры и автоматизация

- К. ID параметров стабильны; новые — только в конец; нет коллизий хешей.
- В. Имена параметров понятны вне окна; `getText`/`getValueForText`
  совпадают с текстами редактора; правильные `getNumSteps`/`isBoolean`.
- В. Изменения из интерфейса обрамлены жестами begin/end; изменения от
  хоста не отправляются обратно («эхо») и не озвучиваются.
- У. Способ включить автоматизацию с клавиатуры (Ctrl+Shift+A) с честной
  озвучкой результата.

## Реальное время и устойчивость

- К. В `processBlock` нет озвучки, блокировок, выделений памяти, файлов,
  сообщений.
- К. Асинхронные лямбды захватывают `SafePointer`, а не голый `this`.
- К. Компонент не удаляется внутри собственного `keyPressed`.
- В. Тяжёлые операции в фоновом потоке, интерфейс показывает прогресс и
  блокирует команды.
- В. Синхронные вызовы хоста (`getStateInformation`) быстрые (кеш хешей и
  т.п.).

## Сборка

- В. `EDITOR_WANTS_KEYBOARD_FOCUS TRUE`.
- В. Строки с не-ASCII символами в UTF-8 (`String::fromUTF8`).
- У. CLAP и VST3 используют один редактор; поведение одинаковое.
